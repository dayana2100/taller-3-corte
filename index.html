Sistema académico para asistencia con QR temporal

App Attendance es una plataforma demostrativa para gestionar asistencia académica mediante sesiones temporales, código QR de sala, listado de inscritos, resultados e historial. Esta landing está diseñada para Moodle como paquete SCORM y resume la documentación técnica, funcional y de sustentación sin publicar datos sensibles reales.

Problema que resuelve

En una clase presencial o híbrida, tomar asistencia de forma manual consume tiempo, dificulta la trazabilidad y aumenta el riesgo de errores o registros duplicados.

Tiempo operativo

El docente/instructor necesita abrir una sesión, compartir el QR y validar asistencia sin interrumpir la dinámica de clase.

Trazabilidad

La sesión conserva estado, inscritos, presentes, ausentes, rechazos, duplicados e historial consultable.

Control académico

El sistema organiza la asistencia por institución, ficha o materia y evita mezclar estudiantes de unidades diferentes.

Privacidad: para Moodle y sustentación no se deben publicar nombres, documentos, teléfonos, correos, contraseñas, tokens ni URLs reales. Todo ejemplo de este paquete es sintético.

Funcionalidades principales

La documentación del repositorio confirma una app móvil/web Ionic React, una API REST Express y MongoDB local por Docker Compose.

Auth

Login formador

Autenticación de perfiles administrativos, instructor o docente mediante JWT Bearer.

Catálogo

Instituciones

Selección de contexto académico: SENA o universidad, con etiquetas y roles parametrizables.

Unidad

Ficha o materia

Consulta de unidades académicas activas y estudiantes/aprendices inscritos.

QR

Sesión temporal

Creación, activación, expiración y cierre de sesiones de asistencia.

CSR

Código de sala

Código rotativo anti-fraude para reforzar que el registro ocurra durante la clase.

Resultado

Presentes y ausentes

Consulta de registros aceptados y cálculo de inscritos sin asistencia.

Auditoría

Rechazos

Identificación de documentos inexistentes, duplicados, sesiones cerradas o QR expirados.

Moodle

SCORM

Landing empaquetada con manifest, progreso y autoevaluación para importación en Moodle.

Arquitectura técnica

El diseño separa interfaz, API, persistencia, documentación y carga de datos. La app no se conecta directamente a MongoDB. 

Celular del estudiante
    | Escanea QR o ingresa código
    ▼
Formulario público /attendance/:token
    | POST /public/attendance/:token/register
    ▼
API Backend Express + TypeScript
    | Validación Zod · JWT · reglas de negocio
    ▼
MongoDB 7 por Docker Compose

PC docente/instructor
    | Ionic React + Capacitor
    ▼
Rutas /api/* con Authorization: Bearer <JWT>

Capas confirmadas

  • app/: Ionic React, Vite, Capacitor.
  • back/: Node.js, Express, TypeScript, Mongoose, Zod.
  • db/: MongoDB, seed sintético/local.
  • docs/: arquitectura, API, modelo, operación y validación.

Restricciones

  • No conectar frontend directo a MongoDB.
  • No quemar URL real del backend.
  • No publicar datos reales en Moodle.
  • No usar secretos reales en documentación.
  • No depender de capturas con información personal.

Modelo de datos MongoDB

Resumen de colecciones documentadas. Los ejemplos de valores son sintéticos.

Colección Campos clave Responsabilidad Índices / reglas
institutions code, name, context, labels, theme, active Define institución y parametrización visual/semántica. code único.
academic_units institutionId, code, name, type Representa ficha o materia. institutionId + code único.
people institutionId, documento, nombre, matricula, roles Personas del sistema: formadores, aprendices o estudiantes. institutionId + documento único.
enrollments institutionId, unitId, personId, active Relación persona-unidad académica. unitId + personId único.
attendance_sessions institutionId, unitId, status, qrToken, qrExpiresAt Sesión de asistencia temporal. qrToken único sparse.
attendance_records sessionId, personId, documento, status, rejectReason Intento aceptado o rechazado de asistencia. Único parcial para accepted por sesión/persona.
permissions role, resource, action Autorización por rol, recurso y acción. Unión de permisos por roles.

Instalación reproducible para estudiantes

Comandos orientados a Windows/PowerShell y Docker. Ajustar rutas locales según el equipo.

Clonar e instalar

git clone <URL_DEL_REPOSITORIO> app-attendance
cd app-attendance
Copy-Item .env.example .env
npm run install:all

Levantar servicios

npm run docker:up
npm run docker:seed
Invoke-RestMethod http://localhost:4000/health
Invoke-RestMethod http://localhost:4000/ready
npm run dev:app
URL local esperada: frontend en http://localhost:5173 para desarrollo Vite o http://localhost:8080 si se sirve por Docker/nginx. Backend local: http://localhost:4000.

Flujo de consumo frontend

async function login(documento, password) {
  const response = await fetch(`${backendUrl}/api/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ documento, password })
  });

  if (!response.ok) {
    throw new Error('Credenciales inválidas o API no disponible');
  }

  return response.json();
}

Validación de QR

Reglas esperadas:
1. El token debe existir.
2. La sesión debe estar activa.
3. El QR no debe estar expirado.
4. El documento debe pertenecer a la unidad académica.
5. No debe existir asistencia accepted previa para la misma persona.
6. Si falla, registrar rechazo con motivo trazable.

Seguridad y privacidad

La landing y el SCORM deben ser publicables en Moodle sin datos personales reales.

No publicar:

nombres reales, documentos reales, teléfonos, correos, capturas con estudiantes, contraseñas reales, tokens JWT, URLs activas de túneles, contenido de .env real, archivos con seeds privados o información institucional sensible.

Sí publicar:

datos demo, diagramas conceptuales, comandos genéricos, variables con placeholders, capturas anonimizadas, flujos funcionales, checklist de validación y código sin secretos.

Checklist antes de subir a Moodle

Uso como SCORM en Moodle

Este paquete incluye imsmanifest.xml en la raíz, archivo principal index.html, estilos separados y JavaScript separado.

Importar

  1. Entrar al curso.
  2. Activar edición.
  3. Agregar actividad o recurso.
  4. Seleccionar paquete SCORM.
  5. Subir el ZIP completo.
  6. Guardar y mostrar.

Seguimiento

El JavaScript intenta comunicarse con SCORM 1.2 para registrar progreso, ubicación, puntaje de autoevaluación y estado completado/aprobado. Si se abre fuera de Moodle, usa almacenamiento local como respaldo.

Importante: Moodle necesita el ZIP completo. No subir solo el index.html. El archivo imsmanifest.xml debe quedar en la raíz del paquete.
